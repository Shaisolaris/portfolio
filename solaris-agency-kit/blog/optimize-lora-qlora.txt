12:T7972,<h2>👋 Introduction</h2>
<p>As businesses increasingly turn to AI for value generation, the applications of neural network-based techniques and Large Language Models ( <strong>LLMs</strong>) have become pivotal. Advancements in natural language processing have empowered organizations to address various text-related challenges, including classification, summarization, and controlled text creation. While third-party APIs may be convenient, fine-tuning models with proprietary data yields cost-effective and domain-specific solutions that can be securely deployed across various environments. However, choosing the right strategy for fine-tuning is critical.</p>
<p>This blog explores one of the most popular and effective methods for parameter-efficient fine-tuning: <strong>Low-Rank Adaptation (LoRA)</strong>, with a specific focus on <strong>QLoRA</strong>, an even more efficient variant. The goal is to take an open large language model and fine-tune it to generate a proper response based on the given message. For this exercise, we have chosen the <a href="https://huggingface.co/TheBloke/Mistral-7B-Instruct-v0.2-GPTQ">TheBloke/Mistral-7B-Instruct-v0.2-GPTQ</a> model, which is open-source with a permissive license (Apache 2.0), and the <a href="https://huggingface.co/datasets/Samhita/slack-data-long-responses">Samhita/slack-data-long-responses dataset</a>, both available for download from the <a href="https://huggingface.co/">HuggingFace Hub</a>.</p>
<h2><strong>What is PEFT Finetuning?</strong></h2>
<p><a href="https://huggingface.co/docs/peft/en/index">PEFT</a> Fine-tuning, or Parameter Efficient Fine-tuning, is a set of techniques designed to make model training more efficient. Traditional training methods often involve a large number of trainable parameters, which can be resource-intensive and time-consuming. PEFT techniques, such as <strong>Prefix Tuning</strong>, <strong>P-tuning</strong>, and <strong>LoRA</strong>, reduce the number of parameters, leading to faster and more cost-effective training. For example, in natural language processing, PEFT techniques have been used to improve model performance while reducing resource consumption.</p>
<h3><strong>Benefits of PEFT Fine-tuning</strong></h3>
<p>Parameter Efficient Fine-tuning ( <a href="https://huggingface.co/docs/peft/en/index">PEFT</a>) offers several compelling benefits, particularly for enterprises and large businesses seeking to fine-tune Large Language Models (LLMs) like <strong>BERT</strong> and <strong>GPT</strong>. These benefits include:</p>
<ol>
<li><strong>Time Savings</strong>: By reducing the number of trainable parameters, PEFT accelerates both the training and testing processes. This efficiency allows for quicker exploration of different models, datasets, and techniques, ultimately saving valuable time in model development and deployment.</li>
<li><strong>Cost Efficiency</strong>: PEFT's memory optimizations enable training on less powerful computational resources, resulting in reduced costs associated with training on large datasets. This cost-effectiveness makes PEFT particularly attractive for businesses looking to scale their AI capabilities without significantly increasing their infrastructure costs.</li>
<li><strong>Improved Model Performance</strong>: Despite the reduction in trainable parameters, PEFT techniques often lead to improved model performance. By focusing on optimizing the most important parameters, PEFT can enhance the overall effectiveness and accuracy of LLMs, leading to better results in various natural language processing tasks.</li>
</ol>
<h2>What is LoRA &#x26; QLoRA?</h2>
<p><a href="https://arxiv.org/abs/2106.09685">LoRA</a>, short for Low-Rank Adaptation, is a breakthrough in the field of LLM. Traditionally, fine-tuning such models involved adjusting all the weights in the pre-trained model's weight matrix. LoRA, however, takes a different approach. It fine-tunes two smaller matrices that approximate the larger weight matrix, known as the <strong>LoRA adapter</strong>. This fine-tuned adapter is then loaded into the pre-trained model for use during inference.</p>
<p><a href="https://arxiv.org/abs/2305.14314"><strong>QLoRA</strong></a> takes this efficiency further by leveraging <strong>quantization techniques</strong>. It loads the pre-trained model's weights onto the GPU memory as quantized <strong>4-bit</strong> weights, as opposed to the <strong>8-bits</strong> used in LoRA. Despite this reduction in memory usage, QLoRA maintains a similar level of effectiveness as LoRA. By probing and comparing these methods, and optimizing QLoRA's hyperparameters, we aim to achieve optimal performance with the quickest training time.</p>
<p>Implemented in the Hugging Face Parameter Efficient Fine-Tuning (PEFT) library, LoRA offers ease of use. QLoRA can be utilized by combining <a href="https://github.com/TimDettmers/bitsandbytes"><strong>bitsandbytes</strong></a> and PEFT. Additionally, We are going to use the HuggingFace <strong>Transformer Reinforcement Learning (</strong> <a href="https://huggingface.co/docs/trl/en/index">TRL</a> <strong>)</strong> library which provides a convenient trainer for supervised fine-tuning with seamless integration for LoRA. These libraries offer the necessary tools to fine-tune a chosen pre-trained model for generating coherent and convincing product descriptions based on specific attributes</p>

<h3>Configure LoRA parameters</h3>
<p>When using <strong>PEFT</strong> to train a model with <strong>LoRA</strong> or <strong>QLoRA</strong>, the hyperparameters of the low-rank adaptation process can be defined in a <strong>LoRA</strong> config. Two key hyperparameters, <strong>"r"</strong> and <strong>"target_modules,"</strong> significantly affect adaptation quality and are the focus of the tests that follow.</p>
<ol>
<li><strong>Rank (r)</strong>: This parameter determines the rank of the low-rank matrices learned during the fine-tuning process. A lower rank may lead to quicker but potentially lower-quality model training. Increasing r beyond a certain value may not yield significant quality improvements. The value of r and its effect on adaptation quality will be tested.</li>
<li><strong>Target Modules</strong>: This parameter specifies which modules in the model architecture to target during LoRA adaptation. While it's common practice to target only the attention blocks of the transformer to reduce training time and compute resources, recent work suggests that targeting all linear layers may improve adaptation quality. <code>‍</code></li>
</ol>

<h2>Best Practices for Fine-Tuning with LoRA and QLoRA</h2>
<ol>
<li><strong>Optimal Scaling Coefficient</strong>: According to the original LoRA paper, choosing the scaling coefficient alpha as two times the rank parameter r often results in the best outcomes. This means setting alpha = 2 * r. However, it can be beneficial to experiment with different ratios to find the optimal configuration for your specific task and model.</li>
<li><strong>Enable LoRA for More Layers</strong>: While experiments often focus on enabling LoRA for select weight matrices, such as the Key and Value matrices in each transformer layer, consider enabling LoRA for additional layers, such as Query matrices, linear layers between multihead attention blocks, and the linear output layer. This can increase the number of trainable parameters and memory requirements but may improve modeling performance noticeably. Learn more about this <a href="https://arxiv.org/html/2402.08562v1">here</a>.</li>
<li><strong>Optimize Adapter Usage</strong>: When using adapters, understand that the size of the LoRA adapter obtained through fine-tuning is typically small compared to the pre-trained base model. During inference, both the adapter and pretrained model need to be loaded, maintaining similar memory requirements. Merging the weights of the pre-trained model and the adapter can slightly increase inference latency but can be done efficiently using the PEFT library with a single line of code.</li>
<li><strong>Consider the Trade-offs of Merging Adapters</strong>: While merging adapters can reduce inference latency, it eliminates the ability to efficiently use a single large pre-trainedmodel with task-specific adapters. The decision to merge weights depends on the specific use case and acceptable inference latency.</li>
</ol>

<h2><strong>What is PEFT Finetuning?</strong></h2>
<p><a href="https://huggingface.co/docs/peft/en/index">PEFT</a> Fine-tuning, or Parameter Efficient Fine-tuning, is a set of techniques designed to make model training more efficient. Traditional training methods often involve a large number of trainable parameters, which can be resource-intensive and time-consuming. PEFT techniques, such as <strong>Prefix Tuning</strong>, <strong>P-tuning</strong>, and <strong>LoRA</strong>, reduce the number of parameters, leading to faster and more cost-effective training. For example, in natural language processing, PEFT techniques have been used to improve model performance while reducing resource consumption.</p>
<h3><strong>Benefits of PEFT Fine-tuning</strong></h3>
<p>Parameter Efficient Fine-tuning ( <a href="https://huggingface.co/docs/peft/en/index">PEFT</a>) offers several compelling benefits, particularly for enterprises and large businesses seeking to fine-tune Large Language Models (LLMs) like <strong>BERT</strong> and <strong>GPT</strong>. These benefits include:</p>
<ol>
<li><strong>Time Savings</strong>: By reducing the number of trainable parameters, PEFT accelerates both the training and testing processes. This efficiency allows for quicker exploration of different models, datasets, and techniques, ultimately saving valuable time in model development and deployment.</li>
<li><strong>Cost Efficiency</strong>: PEFT's memory optimizations enable training on less powerful computational resources, resulting in reduced costs associated with training on large datasets. This cost-effectiveness makes PEFT particularly attractive for businesses looking to scale their AI capabilities without significantly increasing their infrastructure costs.</li>
<li><strong>Improved Model Performance</strong>: Despite the reduction in trainable parameters, PEFT techniques often lead to improved model performance. By focusing on optimizing the most important parameters, PEFT can enhance the overall effectiveness and accuracy of LLMs, leading to better results in various natural language processing tasks.</li>
</ol>
<h2>What is LoRA &#x26; QLoRA?</h2>
<p><a href="https://arxiv.org/abs/2106.09685">LoRA</a>, short for Low-Rank Adaptation, is a breakthrough in the field of LLM. Traditionally, fine-tuning such models involved adjusting all the weights in the pre-trained model's weight matrix. LoRA, however, takes a different approach. It fine-tunes two smaller matrices that approximate the larger weight matrix, known as the <strong>LoRA adapter</strong>. This fine-tuned adapter is then loaded into the pre-trained model for use during inference.</p>
<p><a href="https://arxiv.org/abs/2305.14314"><strong>QLoRA</strong></a> takes this efficiency further by leveraging <strong>quantization techniques</strong>. It loads the pre-trained model's weights onto the GPU memory as quantized <strong>4-bit</strong> weights, as opposed to the <strong>8-bits</strong> used in LoRA. Despite this reduction in memory usage, QLoRA maintains a similar level of effectiveness as LoRA. By probing and comparing these methods, and optimizing QLoRA's hyperparameters, we aim to achieve optimal performance with the quickest training time.</p>
<p>Implemented in the Hugging Face Parameter Efficient Fine-Tuning (PEFT) library, LoRA offers ease of use. QLoRA can be utilized by combining <a href="https://github.com/TimDettmers/bitsandbytes"><strong>bitsandbytes</strong></a> and PEFT. Additionally, We are going to use the HuggingFace <strong>Transformer Reinforcement Learning (</strong> <a href="https://huggingface.co/docs/trl/en/index">TRL</a> <strong>)</strong> library which provides a convenient trainer for supervised fine-tuning with seamless integration for LoRA. These libraries offer the necessary tools to fine-tune a chosen pre-trained model for generating coherent and convincing product descriptions based on specific attributes</p>

<h3>Configure LoRA parameters</h3>
<p>When using <strong>PEFT</strong> to train a model with <strong>LoRA</strong> or <strong>QLoRA</strong>, the hyperparameters of the low-rank adaptation process can be defined in a <strong>LoRA</strong> config. Two key hyperparameters, <strong>"r"</strong> and <strong>"target_modules,"</strong> significantly affect adaptation quality and are the focus of the tests that follow.</p>
<ol>
<li><strong>Rank (r)</strong>: This parameter determines the rank of the low-rank matrices learned during the fine-tuning process. A lower rank may lead to quicker but potentially lower-quality model training. Increasing r beyond a certain value may not yield significant quality improvements. The value of r and its effect on adaptation quality will be tested.</li>
<li><strong>Target Modules</strong>: This parameter specifies which modules in the model architecture to target during LoRA adaptation. While it's common practice to target only the attention blocks of the transformer to reduce training time and compute resources, recent work suggests that targeting all linear layers may improve adaptation quality. <code>‍</code></li>
</ol>

<h2>Best Practices for Fine-Tuning with LoRA and QLoRA</h2>
<ol>
<li><strong>Optimal Scaling Coefficient</strong>: According to the original LoRA paper, choosing the scaling coefficient alpha as two times the rank parameter r often results in the best outcomes. This means setting alpha = 2 * r. However, it can be beneficial to experiment with different ratios to find the optimal configuration for your specific task and model.</li>
<li><strong>Enable LoRA for More Layers</strong>: While experiments often focus on enabling LoRA for select weight matrices, such as the Key and Value matrices in each transformer layer, consider enabling LoRA for additional layers, such as Query matrices, linear layers between multihead attention blocks, and the linear output layer. This can increase the number of trainable parameters and memory requirements but may improve modeling performance noticeably. Learn more about this <a href="https://arxiv.org/html/2402.08562v1">here</a>.</li>
<li><strong>Optimize Adapter Usage</strong>: When using adapters, understand that the size of the LoRA adapter obtained through fine-tuning is typically small compared to the pre-trained base model. During inference, both the adapter and pretrained model need to be loaded, maintaining similar memory requirements. Merging the weights of the pre-trained model and the adapter can slightly increase inference latency but can be done efficiently using the PEFT library with a single line of code.</li>
<li><strong>Consider the Trade-offs of Merging Adapters</strong>: While merging adapters can reduce inference latency, it eliminates the ability to efficiently use a single large pre-trainedmodel with task-specific adapters. The decision to merge weights depends on the specific use case and acceptable inference latency.</li>
</ol>
